## Unreleased

 * [perf] `is_valid_geohash` no longer builds a 32-character set on every call; the valid-character set is precomputed at import and the check runs as a single set operation, roughly 3x faster on typical inputs.
 * [perf] `get_adjacent` no longer emits per-call debug logging and no longer recurses on border characters: it walks the hash right-to-left using precomputed neighbor/border lookup tables. Typical lookups are ~2x faster and border-wrap (e.g. antimeridian-crossing) lookups several times faster. Validation outcomes, adjacency results (including the `u00000` -> `gbpbpb` wrap), case-insensitive input handling, and error messages are unchanged. Logging-plumbing tests that relied on `get_adjacent`'s per-call debug records now exercise other debug emitters or the module's error-path records.
 * [tests] added pytest-benchmark cases for `get_adjacent` (typical and border-wrap) and `is_valid_geohash`.
 * [perf] `geohashes_in_box` now enumerates grid cells directly instead of sampling a half-cell-spaced point grid: it derives the cell size once, walks the covering index rectangle, includes interior cells without checks, and intersection-tests only boundary cells. A 0.1 deg x 0.2 deg box at precision 6 (361 cells) drops from ~2.3 ms to ~0.37-0.43 ms (>5x, 11x locally measured); small boxes improve ~6x. Membership is unchanged, verified against the previous implementation on 215 randomized and edge-case boxes across all precisions.
 * [behavior] `geohashes_in_box` now returns a deterministically sorted list. The previous implementation returned `list(set(...))`, whose order varied across processes; existing callers that sorted the result no longer need to.

v3.3.2
======

 * [bugfix] **behavior change:** constructing a `BoundingBox` with `min_lat > max_lat` or `min_lon > max_lon` now raises a `ValueError` naming the offending pair and the interleaved `(min_lat, min_lon, max_lat, max_lon)` field order. The grouped-argument mistake `BoundingBox(min_lat, max_lat, min_lon, max_lon)` previously produced an inverted box that silently degraded everywhere - `geohashes_in_box` returned `[]`, `is_point_in_box` returned False, and a box did not intersect itself. Boxes written to span the antimeridian, which the library does not support, are rejected by the same check. Degenerate boxes where a minimum equals its maximum remain valid, and no box `get_bounding_box` produces is affected.
 * [bugfix] strengthened validation across encoding, decoding, adjacent-cell lookup, bounding boxes (including out-of-world and boolean coordinates), collection statistics, Pandas Series detection, and visualization collection inputs; invalid values now fail consistently instead of producing misleading results or low-level errors.
 * [bugfix] decoding and `geohash_approximate_distance` now accept uppercase and mixed-case geohashes, and cardinal selectors preserve the caller's original geohash string.
 * [bugfix] fixed antimeridian behavior in adjacent-cell traversal, circular longitude means, and Folium grid viewports near world boundaries.
 * [bugfix] fixed missing cells at bounding-box corners and corrected visualization imports for isolated `viz` installations.
 * [bugfix] logging helpers now emit records at their requested level and avoid doubled `pygeohash.pygeohash.*` logger names.
 * [perf] optional modules remain lazy until their public attributes are first accessed.
 * [packaging] publication now smoke-tests built wheels and source distributions, and Linux ARM64 wheels are built natively.
 * [docs] published the cross-library benchmark comparison as a README section and `docs/source/benchmarks.rst`, generated by `scripts/run_comparison_benchmark.py`.
 * [tests] dependency-free docstring examples are now verified as doctests, and the randomized accuracy check fails on codec regressions instead of passing them over.

v3.3.1
======

 * [bugfix] `encode`/`encode_strictly` in the C extension now reject a precision outside 1-12 with a ValueError. Calling `pygeohash.cgeohash.geohash_module.encode` directly with a larger precision previously overran a fixed-size buffer.
 * [bugfix] the C encoders now reject NaN and infinite coordinates with a ValueError. Passing an infinite longitude previously hung the call.
 * [bugfix] `geohash_approximate_distance` now returns 0.0 for two identical geohashes instead of the precision-table value for their shared prefix.
 * [bugfix] `geohashes_in_box` now clamps its sampling range to latitude +/-90 and longitude +/-180, so boxes touching the world limits enumerate correctly.
 * [bugfix] `plot_geohashes` works again with matplotlib >= 3.9, which removed `matplotlib.cm.get_cmap`.
 * [packaging] the `py.typed` marker is now shipped in the wheel and sdist, so type checkers finally see pygeohash's inline type hints. The "Typing :: Typed" classifier is now accurate.
 * [docs] `encode_strictly` no longer claims to perform extra validation. It is identical to `encode` and is kept only as a back-compatible alias.

v3.3.0
======

 * [perf] reworked the C decode path: cache the LatLong/ExactLatLong types instead of importing them per call, decode straight into a LatLong without building and discarding an intermediate ExactLatLong, and construct the result tuple directly (decode ~3x faster, bounding box ~1.5x faster)
 * [perf] trimmed the Python wrappers: dropped redundant per-character validation (the C extension already validates) and per-call debug logging from the encode/decode/bounding-box hot paths
 * [bugfix] fixed a latent out-of-bounds read in the C decoder for input bytes >= 128 (e.g. multibyte UTF-8); these are now cleanly rejected as invalid characters
 * [tests] added a cross-library benchmark suite comparing pygeohash against other geohash libraries, behind an optional 'benchmark' extra
